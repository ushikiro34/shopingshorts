# 04. UI 스펙 — 대시보드 (v2: 로그인 + 탭 + 3단 레이아웃)

> `app/web/`(FastAPI+Jinja2) 구현 시 이 문서를 기준으로 한다. 화면 3개(대시보드홈, 대본작성탭, 게시검토탭)는 목업 이미지로 확정, 나머지는 텍스트 스펙.

## 전체 화면 계층

```
로그인 → 대시보드(홈) → 탭 4개(발굴 / 대본작성 / 미디어제작 / 게시검토)
                              └─ 탭 하나 = 좌(목록) · 중앙(작업영역) · 우(액션) 3단 레이아웃
                              └─ "게시검토" 탭이 곧 최종 게시 결정 화면
```

탭은 페이즈 1:1 매핑이 아니라 **파이프라인 단계 1:1**이다 (발굴=Phase1, 대본작성=Phase2, 미디어제작=Phase3, 게시검토=Phase4). 탭 이동에는 제약이 없다(소프트 게이팅, 아래 상세).

## 톤 & 스타일 가이드

깔끔하면서 캐주얼한 톤을 다음으로 구현한다.
- 코너는 12~16px로 넉넉하게 둥글게, pill 배지(탭·상태)는 완전 라운드
- 색은 CDS 룰 그대로 절제 — accent(진행중)/success(완료)/gray(대기)/danger(즉시실행 경고)만 쓰고 뷰당 primary 버튼 1개
- 문구는 딱딱한 관리자 말투 대신 편한 존댓말("~해요", "확인해주세요"), 이모지는 대시보드 인사말 정도에만 절제해서 사용, 나머지는 Tabler 아이콘
- 여백은 넉넉하게, 빽빽한 표보다 카드 위주

## 0. 로그인 화면

*목업 없음, 텍스트 스펙*

- 단일 운영자 계정 — Supabase Auth 이메일/비밀번호. 회원가입 화면은 없다(계정은 Supabase 대시보드에서 수동 생성).
- 중앙 카드: 이메일·비밀번호 입력 + [로그인] 버튼. 실패 시 "이메일 또는 비밀번호를 확인해주세요."
- 세션은 httpOnly 쿠키(`SESSION_SECRET`으로 서명), 만료 시 로그인 화면으로 리다이렉트.
- 로그인 전 모든 라우트는 접근 불가(미들웨어에서 세션 검증).

## 1. 대시보드 (홈)

*목업 확정 (위 위젯 참조)*

- 로그인 직후 첫 화면. 캐주얼한 인사 문구 + "오늘 목표 N편 중 M편 게시완료" 진행 요약
- 4개 요약 카드(발굴대기/대본검수/제작중/게시대기), 게시대기가 1건 이상이면 카드 배경을 warning 톤으로 강조(주의 환기)
- 카드 클릭 → 해당 탭으로 이동
- 정책 알림 배너(미검토 policy_alerts 있을 때만, 대시보드 상단 고정)
- 하단에 탭 바 미리보기(그대로 탭 4개와 동일, 클릭하면 이동)

## 2. 탭 구성과 소프트 게이팅

- pill 탭 4개: 발굴 / 대본작성 / 미디어제작 / 게시검토. **항상 클릭 가능** — 잠금 없음.
- 각 탭 진입 시 좌측 목록이 비어있으면(해당 단계까지 온 항목이 없음) 안내 배너 표시: "아직 이 단계로 넘어온 상품이 없어요." + [이전 탭으로] 버튼. 클릭을 막지 않고 안내만 한다.
- 실질적인 순서 강제는 **데이터 흐름 자체**가 담당한다 — 예를 들어 대본이 아직 승인되지 않은 상품은 애초에 "미디어제작" 탭의 큐에 나타나지 않으므로, 사용자가 탭을 자유롭게 넘나들어도 순서가 자연히 지켜진다. UI는 상태를 안내할 뿐 차단하지 않는다.
- 각 탭 pill에 해당 단계 대기 건수 배지(예: "대본작성 (1)")

## 3. 탭 공통 3단 레이아웃

모든 탭이 같은 골격을 공유한다.

| 영역 | 데스크톱 | 모바일(<768px) |
|---|---|---|
| 좌: 목록 | 고정 폭 ~120px, 해당 단계 대기 큐 | 기본 화면(풀스크린 리스트), 항목 탭 시 중앙으로 전환 |
| 중앙: 작업영역 | 가변, 최소 320px | 항목 선택 시 풀스크린, 상단 '← 목록' 버튼으로 복귀 |
| 우: 액션 패널 | 고정 폭 ~140px | 하단 고정 액션 바로 축약 |

우측 액션 패널의 마지막 버튼은 공통 패턴 — **"완료하고 다음 단계로"**. 누르면 해당 항목의 status가 다음 파이프라인 단계로 전이되고(예: `script_approved`), 자동으로 다음 탭의 좌측 큐에 나타난다는 토스트 안내("완료! 미디어제작 탭에서 확인할 수 있어요")가 뜬다.

탭 이동 여부는 탭마다 다르다: **발굴 탭**의 "분석 시작하고 다음으로"는 사용자 요청(2026-07-14)으로 대본작성 탭까지 바로 이동한다. 그 외 탭(대본작성/미디어제작/게시검토)은 탭 자체를 강제로 넘기지 않는다 — 사용자가 원할 때 직접 다음 탭을 클릭한다.

### 3-1. 발굴 탭

- 좌: 발굴된 상품 목록, 점수순 정렬(80점 이상 강조 배지 — 상품목록 목업의 배지 규칙 재사용)
- 중앙: 선택 상품 상세(실사 이미지, 가격, 점수 breakdown 7항목), 리뷰 붙여넣기 textarea + 별점요약 입력, `needs_education` 토글(자동 판정값 표시 + 수동 override)
- 우: [새로 발굴하기](모달: URL 또는 키워드 입력), [분석 시작하고 다음으로](리뷰 저장 + `analyze-reviews` 호출)

### 3-2. 대본작성 탭

*목업 확정 (위 "대본작성 탭" 3단 위젯 참조)*

- 좌: 분석완료(`analyzed`) 이상 상품 큐
- 중앙: 구조 5필드 카드(공감/감정/문제제기/해결/상품) 인라인 편집, `educational_note`는 조건부로 별도 카드(정보 아이콘, `bg-accent` 배경)로 구분 표시
- 우: 톤 배지 + [다른 톤으로 재생성] 드롭다운(7종), [승인하고 다음으로]

### 3-3. 미디어제작 탭

- 좌: 승인된 대본(`script_approved`) ~ 렌더링중/완료 큐. 렌더링중 항목은 스피너 + 진행 단계 텍스트("이미지 준비중" → "음성 생성중" → "영상 조립중")
- 중앙: 완성 영상 미리보기(`<video>`) + 썸네일 미리보기, 유튜브 제목/설명 카드(복사 버튼, 고지문구·딥링크 포함 여부 자동 체크 아이콘)
- 우: [썸네일 다시 생성], [게시 준비하고 다음으로](`queue-upload` 호출)

### 3-4. 게시검토 탭 (= 최종 게시 결정 화면)

*목업 확정 (위 게시 검토 위젯 참조)*

- 좌: 게시 대기 큐 — 냉각중/게시가능/게시완료 상태 배지로 구분
- 중앙: 선택 항목의 최종 확인(영상+썸네일+제목/설명 한눈에)
- 우: `pending_review`는 남은 냉각시간만 + [취소]. `ready_to_publish`는 경고 문구(`text-danger`, "클릭 시 즉시 유튜브에 업로드됩니다") + [취소]/[게시]. [게시] 클릭 시 확인 다이얼로그("정말 게시할까요? 되돌릴 수 없어요")를 한 번 더 거친다 — 냉각기간(시간) + 명시적 클릭 + 확인 다이얼로그, 3중 안전장치.
- 인스타그램용은 이 탭에 [mp4 다운로드] 버튼만 별도 제공(API 자동 게시 없음)

## 상태-탭 매핑 (소프트 게이팅의 데이터 근거)

| products.status | 나타나는 탭 |
|---|---|
| discovered, scored, reviews_collected | 발굴 |
| analyzed, script_generated | 대본작성 |
| script_approved, media_generated, thumbnail_generated | 미디어제작 (렌더링 진행률로 세분 표시) |
| queued_for_upload | 게시검토 |
| uploaded | 어느 탭에도 안 뜸 — 대시보드 홈에만 "게시완료" 누적 카운트 |

## 정책 알림 배너 (전역, 조건부)

- `GET /api/policy-alerts?reviewed=false` 1건 이상이면 모든 화면 상단 고정
- 배너 탭 → 알림 목록(탭바 밖 별도 라우트): 플랫폼/정책명/변경일 + [정책 페이지 열기] + [검토완료]
- 배너는 건수만 요약, 개별 확인은 목록 화면에서

## 접근성/반응형 공통 메모

- 버튼 터치 영역 최소 44px
- 3단 레이아웃의 모바일 붕괴는 "화면 전환식"이지 축소 배치가 아니다 — 3열을 그대로 줄이면 글자가 안 보이므로, 좌/중/우를 순차 풀스크린 화면으로 바꾼다
- 탭 바는 모바일에서도 상단 고정, 가로 스크롤 가능한 pill 리스트
