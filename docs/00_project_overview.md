# 00. 프로젝트 개요 v2 — 배경과 결정사항

## 목적 변경 이력

v1은 "쿠팡 리뷰 → 대본 → 영상"의 단순 변환 파이프라인이었다. ChatGPT와의 별도 논의(2026-07 목요일 대화)를 거쳐 **"영상 만드는 AI가 아니라 상품을 고르고, 후기를 분석하고, 타겟에 공감하는 대본을 쓰는 AI 직원 팀"**으로 재정의했다. 핵심 통찰:

- 완전 자동화보다 **작은 AI 직원을 하나씩** 만들어 붙이는 게 성공 확률이 높다 (숨은그림찾기 채널을 캐릭터→프롬프트→썸네일 순으로 점진 발전시켰던 경험과 동일한 패턴).
- 후기는 복사가 아니라 **분석**이 가치다. 원문 재배포보다 "40~50대는 이 표현에 반응한다"는 인사이트가 대본 품질을 만든다.
- 상품 선정 단계(0/1호 직원)를 후기 수집보다 먼저 둬야 한다 — 아무 상품이나 후기를 모으는 게 아니라 "쇼츠로 만들 가치가 있는 상품"을 먼저 걸러야 함.
- 미술치료사 경험을 살려 "공감 → 감정 → 문제제기 → 해결 → 결과 → 상품(CTA)" 구조를 대본의 기본 골격으로 삼는다.

## 운영 규모와 리스크 원칙 (v2.1)

목표 처리량을 **하루 3편**으로 확정했다. "AI 직원이 대량생산하고 나는 검수만"이라는 방향은 유지하되, 이 볼륨에서는 처리량보다 실패율·리스크 최소화가 우선이다. 이에 따라 두 가지를 v2에서 더 보수적으로 조정한다.

1. **업로드는 최종 클릭까지 자동화하지 않는다.** 냉각기간(기본 240분) 동안은 내부 상태만 전환되고, 실제 유튜브 업로드는 사람이 대시보드에서 명시적으로 눌러야 실행된다. 하루 3편이면 수동 클릭 3번의 비용은 무시할 수준이고, 타이머로 자동 게시했을 때 생기는 오발행 리스크가 더 크다.
2. **AI 실사 이미지 생성(Nano Banana/Imagen 등)은 로드맵에서 제외한다.** 상품 이미지는 파트너스 API의 실사진만 사용한다. 라이프스타일 합성 이미지는 상품 왜곡·초상권·아동 등장 리스크가 있고, 하루 3편 규모에서는 실사진 기반으로도 충분히 목표를 채울 수 있다. 필요성이 실제로 입증되면(예: 전환율 데이터) 별도로 재검토한다 — Phase 5에도 기본 포함하지 않는다.
3. **상품 스코어링 임계값을 상향한다.** 하루 3편만 필요하므로 후보를 더 깐깐하게 거를 여유가 있다. 권장 임계값 70→**80점 이상**만 검토 대상으로 삼는다.
4. **이미지는 C안(실사 상품 + 2D 그래픽 배경)으로 확정한다.** 실사+AI합성은 초상권·아동등장·소비자오인·기술적 아티팩트·운영복잡도가 모두 높았고, 순수 2D는 리스크는 없지만 신뢰도가 약했다. 상품은 실사진 그대로, 배경·장식만 2D 그래픽(그라디언트, 아이콘, 카드)으로 채워 두 방식의 리스크를 모두 피한다. 인물(가상 인물 포함)은 영상에 등장시키지 않는다.
5. **Suno는 BGM 전용으로만 쓰고, 실시간 API 연동은 하지 않는다.** Suno는 공식 API가 없고 시중의 "Suno API"는 전부 비공식 서드파티 래퍼라, 하루 3편 자동 파이프라인에 실시간으로 물리면 Suno 본사가 인가하지 않은 우회 접근에 의존하게 된다. 대신 Suno Pro 웹앱에서 월 1회 배치로 인스트루멘털 BGM 10~20곡을 미리 만들어 Storage에 저장하고, 렌더링 시 무작위로 선택해 쓴다. TTS(내레이션)는 Suno가 애초에 적합하지 않은 용도라(노래 부르기 vs 발화) ElevenLabs를 그대로 유지한다.

## 10단계 파이프라인 (AI 직원 매핑)

```
[1] 상품 발굴        — 0/1호 직원: 후보 상품 조사 + 점수화
[2] 후기 수집        — 사람이 수동 복사 (크롤링 금지, 절대규칙 1)
[3] AI 후기 분석      — 2호 직원: 원문 재배포 없이 감정/불만/칭찬 추출
[4] 타겟 선정        — 분석 결과 기반 페르소나 매칭 (기본: 40~50대 여성)
[5] 대본 작성        — 3호 직원: 구조+톤 이중 프롬프트
[6] 이미지 생성      — 4호 직원: 상품 이미지 가공 (1차: 정지이미지, 확장: Kling)
[7] 음성 생성        — 4호 직원: ElevenLabs TTS
[8] 쇼츠 제작        — 5호 직원: FFmpeg 조립 (Ken Burns + 자막 + BGM)
[9] 썸네일 제작      — 5호 직원: 대본 훅 기반 썸네일 자동 생성
[10] 업로드 준비     — 홀드 큐 → 사람 검수 가능 시간 확보 후 자동 게시
```

## 왜 리뷰 크롤링을 여전히 안 하는가

ChatGPT 대화에서도 "Selenium으로 후기 읽기"가 기술적으로 가능한 옵션 2로 제시됐지만, 채택하지 않는다. 파트너스 계정은 쿠팡 로그인 계정과 직접 연결되어 있어 감지 시 계정 정지·미지급 수익 몰수로 이어질 수 있고, 이 리스크는 자동화로 얻는 시간 절약보다 크다. 대신 리뷰 수집은 사람이 하고(1분 이내 작업), **분석부터 자동화**한다 — 이는 ChatGPT 대화의 최종 결론과도 일치한다 ("후기를 그대로 복사하는 직원보다 분석하는 직원이 훨씬 가치 있다").

## 파트너스 API 키 미발급 기간의 임시 소싱 방식 (v2.2)

쿠팡 파트너스 오픈API 키(Access/Secret)는 심사·발급까지 시간이 걸릴 수 있다. 그 기간에도 파이프라인 개발·운영 감각을 익히기 위해 다음 임시 경로를 둔다.

- **상품 등록**: `POST /api/products/manual`로 API 호출 없이 사람이 직접 상품명·가격·카테고리·이미지를 입력해 등록한다. `discover`(자동)와 결과물(상태·점수 체계)은 동일하다.
- **리뷰 수집**: 어느 오픈마켓(쿠팡/네이버쇼핑/11번가 등)의 후기든 사람이 수동 복사해 입력해도 무방하다 — 원래도 리뷰는 크롤링 없이 사람이 입력하고(절대규칙 1), AI 분석 단계에서 감정/불만/칭찬으로 재구성될 뿐 원문이 그대로 대본에 실리지 않으므로(절대규칙 2), 리뷰의 출처 마켓이 최종 산출물의 정확성·저작권 리스크에 영향을 주지 않는다.
- **구매 링크(딥링크)**: 최종적으로는 반드시 쿠팡 상품이어야 한다(수익화 모델이 쿠팡 파트너스 커미션이므로). 사람이 쿠팡 파트너스 웹사이트(partners.coupang.com, 파트너스 ID 계정)에서 동일/동등 상품의 딥링크를 수동 생성해 `PATCH /api/products/{id}/deeplink`로 등록한다.
- 파트너스 API 키가 발급되면 `discover` 자동 경로로 전환하고, 이 임시 경로는 계속 병행 가능한 보조 수단으로 남겨둔다(수동 소싱이 필요한 특수 케이스 대응용).

## 왜 업로드를 "홀드 후 자동"이 아니라 "냉각기간 후 수동 클릭"으로 바꿨는가

v1은 업로드를 절대 금지했고, v2 초안은 "홀드 시간 경과 시 자동 게시"였다. 이번에 하루 3편으로 목표를 확정하면서 다시 조정했다. 자동 게시가 주는 이득(사람이 놓쳐도 게시된다)은 볼륨이 클 때만 의미가 있는데, 하루 3편에서는 사람이 대시보드를 하루 한 번만 확인해도 충분히 커버되는 양이다. 반면 자동 게시가 안고 있는 리스크(대본 오류·부적절한 이미지·잘못된 상품 매칭이 그대로 올라가는 것)는 볼륨과 무관하게 동일하다. 그래서 **자동은 "게시 가능" 상태로 만드는 것까지**로 하고, **실제 업로드 API 호출은 사람의 클릭이 트리거**하도록 바꿨다. 냉각기간(기본 240분)은 남겨서 "렌더링 끝나자마자 대충 보고 바로 게시" 하는 습관을 막는 완충장치로만 쓴다.

| 항목 | 배점 | 근거 |
|---|---|---|
| 리뷰 개수 | 20 | 신뢰도 지표 |
| 최근 리뷰 증가속도 | 20 | 트렌드성 |
| 가격 (충동구매 임계값 이하일수록 가점) | 10 | 전환율 |

| 계절성 매칭 | 10 | 현재 시즌 적합도 |

| 공감 스토리 가능성 | 10 | 리뷰에 감정 표현이 풍부한가 |
| **합계** | **100** | 70점 이상만 사람에게 추천 |

## 대본 설계: 구조 + 톤 이중 프롬프트

- **구조 (고정, 6단계, v2.3)**: 공감(약 3초) → 감정(약 4초) → 문제 제기(약 6초) → 해결(약 8초) → 결과(약 5초) → 상품(약 6초). 초 배분은 참고용 가이드다. "결과" 단계는 해결 방향대로 했을 때의 실제 효과를 리뷰의 긍정 후기로 재구성해 보여준다. CTA는 별도 단계가 아니라 "상품" 단계 마지막 문장에 포함한다.
- **가격 미표기 + 본문 유도 (v2.2)**: narration/구조/썸네일 텍스트 어디에도 가격을 숫자로 표기하지 않는다 — 가격은 변동될 수 있고 쿠팡 딥링크를 눌러야 최신가를 확인하게 만드는 편이 전환에 유리하다. CTA는 "제품정보(가격 포함)는 본문에 있어요, 확인해보세요" 같은 톤으로 "본문/더보기/설명란" 등 링크 확인을 유도하는 표현으로 마무리한다.
- **고지문구 위치 (v2.2)**: `PARTNERS_DISCLOSURE` 문구는 narration(음성)에는 절대 넣지 않고, `youtube.description`의 맨 마지막 줄에만 정확히 그대로 넣는다. 영상 내 시각적 고지(마지막 장면 오버레이)는 Phase 3에서 `disclosure` 필드를 별도로 사용하며 음성 낭독과는 무관하다.
- **톤 (7종, 상품/채널 성격에 따라 선택)**: 불편해결, 우월감, 보상, 생활팁, 사실형, 생활형, 실리적
- 후기 분석 결과([3]단계 산출물)의 감정 키워드를 훅 문장에 직접 반영한다. 예: 분석 결과에 "갱년기", "새벽에 깬다"가 반복되면 훅은 "요즘 새벽마다 깨시나요?"처럼 만든다.
- 기본 타겟: 40~50대 여성. 상품별로 타겟 재조정 가능(예: 야외 작업자 → 자외선 상품).
- **사실설명(educational_note, 선택적)**: 자외선차단·살균·정수필터 등 "왜 필요한지"가 설득력을 좌우하는 카테고리는 문제제기 단계에 간단한 사실 설명을 붙인다(예: 자외선A/B가 노화·화상을 유발할 수 있다는 상식 수준 설명). 대상 카테고리는 키워드 매칭으로 자동 판단(`products.needs_education`)하되 사람이 재검토 가능하다. 이 필드는 마케팅 카피보다 정확성 기준이 높아 별도 검증 규칙(진단·치료 암시 금지어 검사, 절제된 어투 요구)을 둔다 — 상세는 `03_interfaces.md` 4·8번, `phase2_checklist.md` 참조.

## 배포 채널과 정책 모니터링

유튜브 쇼츠뿐 아니라 인스타그램 릴스에도 배포할 계획이다. 채널이 늘어나면 리스크도 늘어나므로 다음을 원칙으로 한다.

- **인스타그램은 1차로 API 자동 게시를 만들지 않는다.** 완성 mp4를 다운로드해 수동 업로드하는 것으로 시작하고, 유튜브 운영이 안정화된 뒤 API 연동(Meta 앱 심사 등 요건이 있음)을 재검토한다.
- **플랫폼 정책은 주기적으로 자동 점검한다.** 유튜브·인스타그램 모두 광고성 콘텐츠·AI 생성 콘텐츠·파트너십 고지 관련 정책이 수시로 바뀔 수 있다. 공식 정책 페이지를 주기적으로 스냅샷 비교해 변경이 감지되면 대시보드에 알림을 띄우는 `policy_checker` 기능을 둔다(Phase 4 부속 기능, 상세는 `03_interfaces.md`, `phase4_spec.md` 참조). 이 기능은 변경 여부만 감지하며, 실제 대응(대본 규칙 수정 등)은 사람이 판단한다.
